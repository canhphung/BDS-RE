## Reference-run data (generated from the original server)

At the user's direction the original BDS was executed locally (see tools/reference/README.md). Two derived artefacts are committed:

- `src/network/block_palette_282.inc`: the 4,493 block states (409 block names) in the original's BlockTypeRegistry order, recovered by tools/reference/make_palette_source.py from the StartGame of a fresh world (seed 318168905) by undoing the original's shuffle; it reproduces the original's palette for other seeds too (checked for seed 123). At start-up BDS-RE shuffles it exactly like BlockPalette::initFromBlockDefinitions (std::shuffle with the level Random seeded with the level seed), so its runtime ids equal the original's for the same seed; the table is sent in StartGame and used for runtime-id lookup.
- `tests/reference/start_game_bds_1.6.0.15.bin`: one complete StartGame body (111,701 bytes) from that run, used by the `level_packets` test to check that BDS-RE reproduces the original encoding byte for byte.

Full captures (including chunk data), the extracted server and the OpenSSL 1.0.2u build stay under the ignored `input/` and scratch directories.

`tests/reference/world_ticks_bds_1.6.0.15.json` is distilled from original-server
GDB traces on 2026-11-17: 4,492 startup RNG words, 112 first-empty-tick words and
32 block sample groups at allocated heights 16/256. Captured values are retained
with source trace hashes/configuration. The flat generator setting is explicitly
selected in GDB and recorded; algorithms and RNG outputs are unmodified. See
`tools/re/export_world_tick_reference.py` and `reverse/reports/RANDOM_TICKS.md`.

`tests/reference/grass_ticks_bds_1.6.0.15.json` contains 160 original
GrassBlock::tick cases from day/night flat-world runs: recorded light/material/
block queries, mutation requests and raw words from separately seeded original
Random objects. The source run hashes and setup commands are retained. It is
generated by `tools/re/gdb_grass_ticks.py` and
`tools/re/export_grass_tick_reference.py`, not by BDS-RE's implementation.

`tests/reference/chunk_order_bds_1.6.0.15.json` retains five original per-player
chunk/item/player/nearby order frames from a two-client run with two dropped
items. It includes both player orders, 75 unique ticked chunks per frame and an
item crossing z=16 whose owner changes one tick after the move is queued.
Captured player lists, offsets and availability are explicit test inputs, not
recorded RNG replay in the runtime. The exporter and source trace hash are
retained; raw binary/capture data remains under ignored `input/`.

Five `tests/reference/lighting_*_bds_1.6.0.15.json` fixtures retain original live
lighting and native tickBlocks outputs: 10,145 sky/block pairs, raw brightness
with both darkening flags, 247 clear-sky time inputs repeated per scene, and
2,560 seeded function calls with all RNG words/LCG boundaries/mutations. The live
five-block material/tick/light registry values are retained too.
`tools/re/export_lighting_reference.py` validates the completed raw trace hash
and native-oracle provenance; it does not calculate expected results.
See `reverse/reports/BLOCK_LIGHTING.md` for inputs, addresses and limits.
